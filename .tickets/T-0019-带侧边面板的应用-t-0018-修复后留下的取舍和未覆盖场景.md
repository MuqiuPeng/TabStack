T-0018 的修复（有自带面板的应用不隐藏，改为把它在其他工作区的标签窗口最小化"停放"；面板点击引起的激活不处理）留下这些取舍，没在本次处理：

- 只在"只显示当前工作区"（`onlyThisWorkspace`，默认开）下生效；关掉这个设置时，面板弹出仍会把被隐藏应用的主窗口带出来。
- 应用切走前就已被隐藏（面板当时不在屏幕上，检测不到）时，面板第一次弹出会先把主窗口带出来，约 0.3 秒后才被停放（会闪一下）。之后同一窗口不会再闪。
- 有面板的应用在别的工作区时，主窗口是最小化而不是隐藏：从别的工作区 ⌘Tab 到它不会出现窗口（Dock 点击可以），焦点跟随也就不会因 ⌘Tab 触发。
- 面板点击会让应用变成前台（应用自身的 bug，见 PortManager 工单），TabStack 不再对这次激活做 place / 跟随切换，但 ≤2 秒后的定时检查会按实际前台更新高亮（当前工作区没有该应用时清掉高亮）。
- 面板识别：屏幕上 0 < layer < 菜单栏层级的窗口（`AX.pidsShowingPanels`）、指针下最上层窗口属于该应用且 layer > 0（`AX.pointerOnPanel`）。只在 Local Runtime 上验证过；画中画、悬浮工具条等可能也被当成面板。

## 验收标准
- [ ] 决定 `onlyThisWorkspace` 关闭时是否也要处理
- [ ] 评估是否需要消除"先闪后停放"（例如记住哪些应用有面板）
- [ ] 至少再用一个别的带浮动面板的应用验证（如 Chrome 画中画）
